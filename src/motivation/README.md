# 动机系统

位置：`src/motivation/`。回答一个问题：**我要什么**。这是五层结构的第五层——把"想要什么"从写死的阈值搬到模型自己手里。

## 五层定位

| 层 | 回答 | 谁写 |
|---|---|---|
| 身体 | 我现在怎么样 | 现实 |
| 经验 | 发生了什么 | 观察 |
| 思考 | 我认为什么 | 模型（判断） |
| 校准 | 我说对了吗 | 现实（对账） |
| **动机（本模块）** | **我要什么** | **模型（心愿）** |

## 工作方式

1. **生成**：定期（`motivation.everyTicks`）让模型面对自己的身体状态、心愿进度和经历，复核已有心愿（keep/drop/adjust 优先级）并写下新心愿（≤3 条）；
2. **心愿必须可核对**：每条心愿带度量 `measure`——`food`（囤粮到 N 份）、`visit`（去某地 N 次）、`explore`（探索 N 次）；进度由系统按现实数据机械计算，不经模型；
3. **达成留档**：进度满 100% 转为 `fulfilled` 并保留——它实现过什么愿望，是它自己的历史；
4. **身体信号降级**：决策提示词在心愿存在时改用自主权衡框架——"bodySignals 是客观状态（顶格耗体力、归零会死），desires 是你的心愿，先后由你自主权衡，你对后果负责"；心愿不存在时保留原有的生存本能措辞；
5. **持久化**：JSON 原子写盘，跨重启携带。

## 心愿账本（与校准系统协作）

心愿写下之后，校准系统按世界当前状态为它记账：该地点此刻有没有食物、多久补充一次、追求窗口内付出了多少、受过几次伤。账本以 `audit` 字段进入复核提示词——`depleted-now` 表示"此刻枯竭但有恢复节律"，不是判死；`harmful` 表示"该地点伤过你"。

模型据此自己决定 keep / drop / adjust。系统不代它做决定。

## 与其他层的边界

- 不修改身体规则——饥饿照旧上涨，死亡照旧发生；变化只在"谁决定怎么回应"；
- 心愿不携带行动指令——和判断一样，是否追求、何时追求由模型在决策时自主权衡；
- 复核失败不阻塞生存。

## 使用

```bash
npm start -- motivations      # 查看心愿与进度
DEER_LIVE_MOTIVATION=0 npm start -- live   # 关闭动机系统
```

配置段 `motivation`：`enabled`、`path`（默认 `data/motivation.json`）、`everyTicks`、`maxActive`、`maxInPrompt`。

测试：`node --test test/motivation.test.ts`。
